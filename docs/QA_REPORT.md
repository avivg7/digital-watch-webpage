## 2. What the tests assert (not only "it renders")

`tests/site.spec.ts`: `lang="he"` `dir="rtl"`, exactly one `h1`, canonical URL, no console error and **no request to any other origin**, **no form, video, audio, iframe, e-mail input, `mailto:` or `tel:`**, no e-mail address or video file reference in any page, no cookies, nothing in `localStorage` until the visitor uses the panel, banned phrases ("מאובטח", "הוכח", "100%", "הצלחנו"…), the exact copyright line with the current year, every `_blank` link has `noopener` and announces the new tab, **every internal link and image resolves**, 404 page, robots and sitemap, JavaScript off, reduced motion.
`tests/gallery.spec.ts`: default image is the work-room screen; six screens; thumbnail click changes image, caption, counter and active marker; wrap-around buttons; **RTL keyboard** (ArrowLeft = next, Home, End); lightbox open, ArrowLeft, focus kept inside, Escape closes and returns focus, close button and click-outside; a failing image shows a message and the gallery keeps working; every screen has a description, a caption and a labelled thumbnail; RTL arrow order; phone lightbox at reading size in a scrollable focusable region.
`tests/a11y-panel.spec.ts`: each adjustment **changes the page** (150% text raises the computed font size by more than 1.4x; high contrast gives `rgb(0,0,0)` and `rgb(255,255,255)`; reduced motion sets the hero animation to `none`; links underline; line height rises), the visible state word changes, settings persist across reload and across pages, reset clears them and the storage key, the live region announces, the four size buttons fit inside the panel at 150% on a phone.
`tests/nav-and-keyboard.spec.ts`: skip link is the first stop and moves focus to `<main>`; second skip link reaches the accessibility button; **45 tab stops each show a focus outline of at least 2 px**; nav moves to sections; phone menu opens, announces, closes on Escape and on an outside tap; CSP present and third-party-free.
`tests/axe.spec.ts`: axe-core (WCAG 2.0/2.1/2.2 A and AA, best practices) on every route, with the panel open and each adjustment on, at 150% text, and with the lightbox open.
`tests/responsive.spec.ts`: widths 320, 390, 768, 1024, 1366, 1440, 1920 on every route: no horizontal scroll, no image outside the viewport (except the filmstrip, a scroll region), hero CTA at least 44 px high; 150% text on a 320 px screen has no horizontal scroll; touch targets at least 44 px.

## 5. What was NOT tested

- **No real screen reader** (VoiceOver, NVDA, JAWS, TalkBack); **no real Safari**, no real iOS or Android device, no real 200%/400% browser zoom (emulated by a 320 px viewport and 150% text); Windows forced-colours mode (rules exist, not run).
- **Slow-network and data-saver behaviour** were not tested; images are lazy and small (205 KB transferred on the home page) but no throttled run was made.
- **The deployed site** is covered by `DEPLOYMENT_EVIDENCE.md`, not by this report.
- **Contrast** was computed for the main pairs (see `ACCESSIBILITY_QA.md`), not measured on rendered pixels for every state.
- **Hebrew copy** was reviewed by AI reviewers and by me, not by a human editor.
- Lighthouse numbers are lab data from one machine and one run each; they are not a promise about field performance.
